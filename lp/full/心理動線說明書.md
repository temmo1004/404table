## 一、為什麼從 v4 升級到 v6（核心差異）

### v4 的問題

v4 雖然心理節奏完整、9 顆 CTA 配置精準、屏 11 未來場景化是高光，但有 5 個短板：

| 短板 | 對 TA 的影響 |
|------|-------------|
| **全文字** | 35-45 滑世代女性對純文字疲勞，**3 秒判定生死**的首屏沒有視覺勾子 |
| **無 Header** | 滑到屏 8 想報名時，得滑回頂端找 CTA，**摩擦極大** |
| **無 Footer** | 滑到底沒著陸點，**信任感不夠**（沒有主辦資訊、聯絡） |
| **無互動感** | 整頁靜態、像 PDF，**不符 LP 期待的「活感」** |
| **RWD 粗糙** | v4 的 `max-width: 680px` 在桌機看起來像手機版被放大，**視覺單調** |

### v6 的解法

**全部對應補強，但不動 v4 已經驗證的心理節奏與 CTA 矩陣**。

| v4 短板 | v6 解法 | 效果 |
|---------|--------|------|
| 全文字 | 整合 25 張電影感寫實人物圖文 | 首屏 0.3 秒勾住、共鳴 5 連發具象化 |
| 無 Header | Sticky Header + 進度條 + 立即報名 CTA | 報名摩擦從 N 屏 → 0 屏 |
| 無 Footer | 4 欄 Footer（品牌 / 講座 / 系列 / 聯絡） | 完整收口、信任建立 |
| 無互動感 | hover lift、fade-up reveal、scroll-snap、pulse dot | 滑動有節奏、卡片有重量感 |
| RWD 粗糙 | 桌機改成圖文左右兩欄 + 1080px 容器寬 | 桌機體驗 = 雜誌級閱讀 |

## 三、Sticky Header 的設計思想

### 為什麼要做 sticky header

**v4 場景**：讀者滑到屏 8 講師故事被打動，想報名。但 CTA 在屏 12，**還要滑 4 屏**。
中間任何一個瞬間想點都得手動滑回頂端找。

**v6 解法**：頂部固定 header，**任何時候想報名都有按鈕**。

### Header 元素設計

```
[● 秘書 AI 自救班 Vol.1 名片] ─────── [5/31 (六) 15:00 ｜ 台北場] [立即報名]
[━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━]  ← 進度條
```

| 元素 | 設計理由 |
|------|---------|
| **● 金點脈動** | 視覺錨點，提示「這是體驗講座、不是免費資訊」 |
| **品牌名 + 副名** | 確認讀者在對的頁面、副名「Vol.1」暗示系列課（為 Tier 2/3 鋪墊）|
| **時間 + 地點** | 中段，**任何時候都看得到「5/31」**，建立急迫感 |
| **立即報名 CTA** | 金色實心、最右側，桌機 hover 上移、手機 active 變亮 |
| **進度條** | 底部 2px 金色漸層，**隨滾動填滿**，給讀者「進度感」 |

### 進度條為什麼重要

- 讀者知道「**還剩多少**」，不會半途放棄
- 12 屏看起來長，但有進度條 = 「**我已經看了 60% 了**」
- 心理學上**沉沒成本**會推著讀者看完

### 半透明 + backdrop-filter 模糊

```css
background: rgba(31, 20, 16, 0.92);
backdrop-filter: blur(12px);
```

- 不完全擋住下方內容
- 在淺色背景滑過時是黑色、在深色背景時無感
- **不破壞情境沉浸**

## 四、卡片式互動的 4 種層次

### 4 個層次（從低到高）

**Level 1：Hover lift（桌機）**
```css
.moment-card:hover {
  transform: translateY(-3px);
  box-shadow: 0 18px 38px rgba(31, 20, 16, 0.08);
}
```
每張場景卡、價值層卡、有形卡、見證卡都有。
**心理效果**：手感重量、值錢感

**Level 2：Reveal fade-up（滾動觸發）**
```javascript
new IntersectionObserver((entries) => {
  entries.forEach(entry => {
    if (entry.isIntersecting) entry.target.classList.add('in-view');
  });
}, { threshold: 0.12, rootMargin: '0px 0px -8% 0px' });
```
每個 `.reveal` 元素進入視窗 12% 時觸發。
延遲 0/0.08/0.16/0.24s 錯開出現，**像舞台燈光**一個一個亮起來。

**心理效果**：
- 不會一次看到全頁、保持新鮮感
- 卡片「**從下面浮上來**」呼應「整理出來」的核心隱喻
- 不會疲勞、每屏都有「**新東西**」進來

**Level 3：Image fade**
圖片 lazy load + 載入後淡入。
即使網路慢，placeholder 也是優雅的深咖啡漸層，**不會破版**。

**Level 4：Pulse dot（稀缺感）**
```css
@keyframes pulse {
  0%, 100% { opacity: 0.6; transform: scale(1); }
  50%      { opacity: 1;   transform: scale(1.4); }
}
```
- 終局「剩 11 名」旁邊脈動紅點
- Mobile CTA Bar 名額旁脈動
- **唯一的動態元素**，不浮誇但有壓迫感

### 為什麼不做更花的互動（如 Lottie、視差、3D 卡）

TA 是 35-45 senior 秘書：
- **滑世代但不耐心**（不愛炫技）
- 期待的是「**穩重值錢**」的感覺
- 太炫的互動會讓她覺得「**這是給年輕人的**」

v6 的互動原則：**只有「重量感」與「節奏感」，沒有「酷炫感」**。

## 五、Mobile 浮動 CTA Bar 的時機設計

### 顯示邏輯

```javascript
const pastHero = window.scrollY > heroBottom - 200;
const inFinalSection = scrolled > finalTop + 200;
if (pastHero && !inFinalSection) show();
```

**邏輯分解**：
- 進入屏 2 時開始顯示（過了 hero）
- 進入屏 12 終局時隱藏（已經有大 CTA、不重複）

### CTA Bar 內容

```
[NT$500 原 1,300]                [我要報名 →]
[● 剩 11 / 30 名 ｜ 5/31 開課]
```

| 元素 | 心理任務 |
|------|---------|
| **NT$500 大字** | 第一眼確認價格（38 歲心算習慣）|
| **原 1,300 劃線** | 價值錨點對比 |
| **剩 11 / 30** | 稀缺壓迫 |
| **5/31 開課** | 時間錨點 |
| **脈動紅點** | 唯一的「催促」視覺 |
| **金色按鈕** | 跟 header CTA 同色，**整頁一致語言** |

### 為什麼桌機不做這個

桌機已經有 sticky header CTA + 8 顆 inline CTA + 終局主 CTA。
再加底部 bar 會**過度設計**、像便宜的 LP。

**手機**：底部 bar 是必要的（拇指滑動範圍）
**桌機**：頂部 header 已經夠

## 六、Footer 的設計理由

### 為什麼 v4 沒做 Footer

v4 結尾是「主 CTA + 保證」，邏輯上夠用。
**但**：滑到底還沒報名的讀者，**信任不夠**才會猶豫。
Footer 提供**信任收口**。

### v6 Footer 的 4 欄

| 欄 | 內容 | 心理任務 |
|----|------|---------|
| 1. 品牌 | 「秘書 AI 自救班 / 別在離職那天才發現妳什麼都沒帶走」 | 整頁主訊息**第二次出現**（記憶錨點） |
| 2. 講座資訊 | 時間、地點、人數、價格 | **不用滑回頂端就能再確認** |
| 3. 系列課程 | Vol.1 / 2 / 3 / 4 | **暗示這是長期系列**（Tier 2/3 種子） |
| 4. 聯絡 | Email、LINE、FAQ、隱私 | **降低疑慮**（有客服等於有人負責）|

### 系列課程露出在 Footer 的策略

```
Vol.1 名片自救（本場）
Vol.2 會議救星 ｜ 6/28
Vol.3 報帳整理 ｜ 7/26
Vol.4 跨國溝通 ｜ 8/23
```

讀者看到「**這是系列課**」會有兩個反應：
1. 「這次沒上也沒關係，下次還有」→ 但其實會錯過獨家內容
2. 「**我可以累積成秘書 AI 自救組合**」→ 上癮感

第 2 反應比第 1 反應強很多（特別是 35-45 senior 秘書喜歡「**累積**」感）。

## 七、字級為 35-45 TA 重新設計的細節

### 字級調整對照（v4 vs v6）

| 元素 | v4 | v6 | 為什麼 |
|------|-----|------|--------|
| body 基準 | 14px / 15.5px | **16.5px** | 35+ 視力衰退、需要更大字 |
| Mobile body | 14.5px | **16px** | 手機上仍然不能小 |
| line-height | 1.95 | **2.0** | 段落呼吸更鬆、不擁擠 |
| letter-spacing | 0 | **0.3px** | 繁體中文需要字距才好讀 |
| 段落間距 | 1em | **1.2em** | 50 字左右的段落需要空間 |
| H1 桌機 | 40px | **42-48px** | 雜誌級閱讀標準 |

### 字型選擇（保留 v4）

```css
font-family: 'Noto Serif TC', '思源宋體', serif;  /* h1, h2, h3, 重要段落 */
font-family: 'Noto Sans TC', '微軟正黑體', sans-serif;  /* 內文 */
```

**為什麼宋體用在重要段落**：
- 宋體有「**書信感、誠懇感**」（不是科技感）
- 對 35+ TA 比較有「**好好說話**」的感覺
- 黑體會讓她覺得「**這是廣告**」

### 段落結構的呼吸感

v6 的每段都遵守：
- 最多 50 字一行
- 一個 idea 一段、不擠
- 段落間 `<br><br>` 空一行
- 重要句子單獨一行

```
這些不是老闆的人脈。
是妳的。
只是妳還沒整理出來。
```

**3 行 3 段、不是擠在一段**，這是 v6 跟 v4 共有的設計（v6 強化）。

## 八、RWD 三斷點設計

### 斷點

```css
/* Mobile（預設） */
< 480px

/* Tablet / 小桌機 */
720px - 1024px

/* 桌機（雜誌級閱讀） */
1024px+
```

### 桌機版的關鍵變化

**Hero 改成左右兩欄**：
```
[文字內容（55%）] [Hero 圖片（45%）]
```
- 桌機讀者眼睛從左到右
- 文字主導、圖片是視覺重量
- 1080px 容器寬，避免「拉太寬」的閱讀疲勞

**場景共鳴卡片改圖文左右**：
```
[圖片（42.5%）] [文字（57.5%）]
```
桌機版每張卡片像雜誌專欄。

**有形 5 件改 2 欄 grid**：
```
[01] [02 關鍵]
[03 模板包 span-2     ]
[04] [05]
```
模板包橫跨 2 欄（因為內容最多）。

**Footer 改 4 欄**：
品牌 / 講座 / 系列 / 聯絡 並排，桌機才有的奢侈。

### 手機版的關鍵保留

- 場景共鳴**保持垂直堆疊**（不做水平 scroll-snap）
  - 理由：5 張中只看 1 張會錯失共鳴累積、必須 5 張都滑過
  - 水平 scroll 在手機 LP 上**反而是壞 pattern**
- 字級保持 16px+
- 卡片內距 24px+（拇指誤觸保護）

## 九、圖片載入策略

### 漸進式載入

```html
<figure class="scene-img" data-img-id="IMG-02">
  <img src="..." loading="lazy" onerror="this.style.display='none'">
  <figcaption>IMG-02</figcaption>
</figure>
```

| 圖位置 | loading | 理由 |
|--------|---------|------|
| Hero IMG-01 | `eager` | 首屏必須立即顯示 |
| 屏 2-12 所有圖 | `lazy` | 滑到才載入、省頻寬 |

### Placeholder 漸層 fallback

每個 `.scene-img` 即使沒有圖也是優雅的深咖啡漸層：

```css
.scene-img {
  background: linear-gradient(135deg, #2a1f17, #3c2415);
}
.scene-img::before {
  content: attr(data-img-id);  /* 顯示 IMG-02 等 */
  color: rgba(201, 169, 97, 0.45);
  /* 高雅的「等待中」狀態 */
}
```

**設計師驗收時的好處**：
- 上線前還沒生成圖，整頁仍然可發
- Placeholder 不像「破圖」，更像**設計感留白**
- 圖片 ID 顯示讓 stakeholder 知道「**這裡會放什麼**」

### 圖片格式

- 主格式：`.webp`（小、快）
- Fallback：`.jpg`（相容性）
- Retina：`@2x` 版本（給大螢幕）

可在 HTML 內升級成 `<picture>` 元素：
```html
<picture>
  <source srcset="images/IMG-01-hero.webp" type="image/webp">
  <img src="images/IMG-01-hero.jpg" alt="...">
</picture>
```
