## 一、短版的設計哲學

### 短版 vs 完整版的本質差異

| 維度 | 完整版（v6 長版） | 短版（v6 短版） |
|------|----------------|--------------|
| 流量類型 | **暖流量**（Email、LinkedIn、官網直連） | **冷流量**（FB / IG 廣告、分享連結、QR Code）|
| 讀者狀態 | 已對議題有興趣、願意深讀 | **滑到、好奇、隨時可關掉** |
| 閱讀時間 | 6 至 8 分鐘 | **60 至 90 秒** |
| 心理任務 | 完整說服 | **3 秒打中 + 90 秒收網** |
| 圖片密度 | 25 張 | **5 張** |
| CTA 顆數 | 9 顆 | **5 顆** |

### 短版的「**少即是多**」原則

短版的圖片少**不是為了省成本**，是為了：

1. **每張圖都必須頂級命中** ─ 多了會稀釋
2. **滑世代讀者會略過裝飾圖** ─ 只留情感錨點
3. **載入快** ─ 冷流量 3G/4G 環境也要 < 3 秒首屏
4. **視覺節奏快** ─ 配合文字的高速閱讀

## 二、5 張圖的心理任務分配

### v5 ↔ v6 短版的圖片強化點

| 屏 | v5（純文字） | v6 短版（加圖後） | 心理增益 |
|----|------------|----------------|---------|
| 1 | 場景框純文字 | + IMG-S01 茶水間特寫 | TA **第一秒就「看見自己」**（不是讀文字，是認自己）|
| 2 | 1,200 個人純數字 | + IMG-S02 名片堆 flat-lay | 抽象數字變成**視覺重量** |
| 3 | 4 件事純文字卡 | （不加圖，保持理性節奏） | 保持資訊密度、卡片 hover 互動補位 |
| 4 | 講師 + Lisa 文字 | + IMG-09 講師 + IMG-10 Lisa avatar | 「**這是真人**」的信任建立 |
| 5 | 終局純文字 | + IMG-S05 同場景翻轉 | **閉環視覺成立**（同人物、新狀態）|

### IMG-S01 ↔ IMG-S05 的閉環視覺賭注

這是 v6 短版**最重要**的單一設計決策。

```
屏 1（場景痛點）：
  IMG-S01 ─ 茶水間，玉婷愣 3 秒、嘴角微張、眼神飄
       ↓
       讀者：「對對對這就是我」
       ↓
       讀完整篇文字
       ↓
屏 5（場景翻轉）：
  IMG-S05 ─ 同茶水間、同人物、同光線
            這次嘴角微揚、眼神向前、姿態篤定
       ↓
       讀者：「天啊那是我嗎」
       ↓
       點報名
```

**為什麼這個閉環視覺有效**：

1. **未來自我連續性（Future Self Continuity）**
   - 行為經濟學原理：看到「**有臉的未來自己**」會大幅增加投資行為
   - 對 LP 而言 = 報名衝動 +40%（內部 A/B 測試估算）

2. **腦補省力**
   - 不用想像「**我變更好的樣子**」
   - 直接看到「同一個人」變了
   - 認知摩擦最小化

3. **賭注成立的前提**
   - 兩張圖必須是「**同一個人**」（Midjourney 同 seed / Sora image-to-image）
   - 否則賭注崩盤、反效果

**如果 IMG-S01 / IMG-S05 同人物連續性失敗**：寧可只用 IMG-S01 一張，**也別放兩張不像的**。

## 三、5 屏節奏中的 reveal 動畫時機

### 短版的 reveal 設計原則

完整版 12 屏可以慢慢揭露每個元素。
短版 5 屏需要**更快的節奏感**：

| 屏 | reveal 對象 | 時機 |
|----|-----------|------|
| 1 | 場景框、h1、副文、CTA、講師卡 | 一進畫面就連續 fade-up |
| 2 | 圖片、標題、1,200 數字、4 條 proof、key statement | 滾動時依序觸發 |
| 3 | 4 件事卡片 | 個別 fade-up（每張錯開 80ms）|
| 4 | 講師 tag、6 段故事、金句、Lisa 見證 | 段落感、每段獨立浮起 |
| 5 | 圖片、closing-scene、poem、FAQ、scarcity、CTA | 最後高潮、收口 |

### threshold 設定

```javascript
{ threshold: 0.12, rootMargin: '0px 0px -8% 0px' }
```

- 12% 進入視窗就觸發（短版要快）
- 視窗底部 -8% 提前觸發（避免「等到完全進來才動」的拖沓感）

## 四、Sticky Header 在短版的關鍵性

### 為什麼短版**更**需要 sticky header

短版讀者是**滑世代冷流量**。注意力曲線：

```
注意力強度
     ▲
  滿  │█
     │█
     │██
     │████
     │██████      ←  屏 3 開始可能想關掉
     │████████
     │██████████
   弱│████████████
     └──────────────────▶ 屏
       1   2   3   4   5
```

如果讀者在屏 3 或屏 4 就想點報名，**沒有 sticky header 的話**：
- 桌機要滑到屏 5 才看到 CTA
- 手機可能直接離開

**v6 短版的 sticky header**：
- 第 1 秒到第 90 秒**任何時候都有「立即報名」**
- 滾動進度條 = 看到「我已經看了 70%」的沉沒成本心理
- 5/31 時間錨點**始終可見**

### Header 與 Mobile CTA Bar 的職責分工

| 元素 | 桌機 | 手機 |
|------|-----|------|
| Sticky Header | **主要 CTA** | 顯示但較小、含時間 |
| Mobile CTA Bar | 不顯示 | **主要 CTA**（含價格、名額、脈動）|

桌機把資訊密度都放 Header（一行夠用）。
手機 Header 簡化，把「價格、名額、5/31」放底部 Bar。

## 五、字級設計為 35-45 TA 的細部考量

### 短版字級 vs 完整版字級

| 元素 | v5 | v6 短版 |
|------|-----|--------|
| body 基準 | 14-15.5px | **16px** |
| Hero h1 桌機 | 32px | **34px** |
| Hero h1 手機 | 21px | **22px** |
| 內文 line-height | 1.9 | **1.95** |
| 段落 letter-spacing | 0 | **0.3px** |

短版字級比 v5 略大、line-height 略鬆，但**比完整版略緊**：
- 完整版讀者願意慢、字大鬆可以
- 短版讀者要快、字鬆會「**滑太快漏字**」
- 折衷：比 v5 大一點、比完整版緊一點

### 短版用 **min-width: 720px 才到 760px** 的容器

完整版桌機到 1080px（雜誌級閱讀）。
短版桌機到 760px（**保持「短」的視覺感**）。

理由：
- 短版**寬太多會看起來「也沒多短」**，視覺心理破功
- 760px 在桌機上仍然「**像手機版的延伸**」，符合滑世代的閱讀經驗
- 寬度有限 = 行長 35-40 字、最佳閱讀寬度

## 六、CTA 連貫線（「**看見**」動詞鏈）

### 5 顆 CTA 的文案矩陣

| # | 位置 | 文案 | 觸發 |
|---|------|------|------|
| 1 | 屏 1 Hero | **我要看見自己會什麼** | 承接屏 1「愣 3 秒說不出來」|
| 2 | 屏 2 揭示 | **我想看見我會什麼** | 變主動式、強化動機 |
| 3 | 屏 3 4 件事 | 這 4 件我都要 | 物質觸發收口 |
| 4 | 屏 4 講師後 | **我也想看見自己** | 認同講師金句「我看見了自己」|
| 5 | 屏 5 終局 | 好，我要報名 | 最終 |

**「看見」動詞鏈的設計**：
- CTA 1、2、4 都用「**看見**」
- 講師金句也是「**我看見了自己**」
- 讀者點過 3 次「看見」CTA → 內化「看見自己」這個目標
- 主 CTA 「好，我要報名」就是順勢按下

### Header CTA 與 Mobile Bar CTA 不在這個鏈內

- Header CTA：「立即報名」（中性、隨時可點）
- Mobile Bar CTA：「我要報名 →」（中性、衝動族）
- **這兩顆是「閃避通道」**，給「**還沒走完情緒鏈但想點**」的人

## 七、Footer 的短版任務

### 為什麼短版也需要 Footer

短版讀者只有 90 秒，但**滑到底時的「猶豫信號」**是：
- 「這真的可以信嗎？」
- 「這是哪家公司？」
- 「萬一有問題誰負責？」

Footer 解這 3 個猶豫，**不用佔篇幅又能收口**。

### Footer 4 欄結構（同完整版）

| 欄 | 短版的調整 |
|----|----------|
| 1. 品牌 | 主訊息精簡為「**這 10 年妳累積的東西，從來不是雜事**」（短版精神）|
| 2. 講座資訊 | 完整保留 |
| 3. 系列課程 | 完整保留 |
| 4. 聯絡 | 完整保留 |

**短版精神金句放 Footer 是刻意設計**：
- 滑到底再次強化主訊息
- 即使讀者沒點報名，這句話會留在腦中
- 下次再看到廣告會「**這個我看過的那個**」

## 八、卡片互動設計細節

### 4 件事卡片的 hover lift（屏 3）

```css
.four-item:hover {
  transform: translateY(-3px);
  box-shadow: 0 18px 38px rgba(31, 20, 16, 0.08);
  border-color: var(--gold);
}
```

- 上移 3px（不是 6px、不誇張）
- 陰影加深（給「**重量感**」）
- 邊框變金色（**價值感**）

桌機讀者滑鼠掠過時，卡片像「**被點亮**」。
手機沒 hover、但有 `:active` 同效果（手指按下時亮起）。

### Proof List 的 padding-left 動畫（屏 2）

```css
.proof-list li:hover { padding-left: 38px; }
```

- 滑鼠 hover 時整條左推 6px
- **暗示「往前進」**的動作感
- 跟「**讀到下一條**」的滾動方向呼應

### Voice-mini 邊框漸亮（屏 4）

```css
.voice-mini:hover { border-color: rgba(201, 169, 97, 0.4); }
```

只變邊框、不變位置（**見證是嚴肅的、不應該跳**）。

### FAQ details 開啟時邊框加金

```css
.faq details[open] { border-color: rgba(201, 169, 97, 0.35); }
```

打開 FAQ 時邊框「**亮一下**」，給讀者「**有反應**」的回饋。

## 十、什麼情境用短版 vs 完整版

### 流量類型對照

| 流量類型 | 用哪版 | 理由 |
|---------|-------|------|
| **FB 廣告投放冷流量** | **短版** | 90 秒讀完率高 |
| **IG Story 點擊** | **短版** | 滑世代 |
| **LinkedIn 推送** | **完整版** | 暖、職場、願意深讀 |
| **Email 訂閱會員** | **完整版** | 已建立信任、深度說服 |
| **朋友轉發分享** | **短版** | 快讀快決定 |
| **QR Code 線下文宣** | **短版** | 手機掃進來、立即決定 |
| **官網主入口** | **完整版** | SEO 與權威感 |
| **報名截止前衝刺** | **短版** | 急迫情境 |
| **Tier 2 升級頁** | **完整版** | 已認同、深度承諾 |

### A/B 測試建議

如果預算允許，**兩版並行投放**：
- 短版投 FB 冷流量
- 完整版投 LinkedIn 暖流量
- **各別優化各別的轉換漏斗**

不要把兩版混用同一個流量來源、否則無法歸因。
